# AGENTS.md

Session learnings for Repo Rizz — things not recoverable by reading the code alone.

## Architecture — as built vs. as documented
- Backend module map (post architecture pass): `python-backend/main.py` is a **composition root** — FastAPI app, middleware, the pre-existing `/analyze` engine API, static page routes — plus `app.include_router(auth_router)` / `include_router(contributors_router)`. Auth endpoints (login/logout/me) live in `admin_auth.py` as `auth_router`; contributor routes + Pydantic validation live in `contributors_api.py` (`router`, with `admin_guard` — one FastAPI dependency enforcing session+CSRF — and `_store_error` mapping 409/500). Persistence is `contributors_store.py` (also owns `is_duplicate_error`), secure files are `uploads.py`. New contributor/admin routes belong in `contributors_api.py`, not `main.py`.
- The "frontend" is static HTML/CSS/JS in `frontend/` served **by** the FastAPI backend (StaticFiles at `/static/` + explicit page routes in `python-backend/main.py`). There is no Next.js app; README's Next.js claims are aspirational. Root `.env.local` (`NEXT_PUBLIC_*`) is now read: normal-user Supabase auth config is served at `GET /api/config/supabase` (only the publishable anon key — never the service-role key from `python-backend/.env`).
- Frontend fetches are same-origin, so the CORS origin list (localhost:3000/8001) is only exercised if pages are hosted separately.
- The `.bat` launchers run the backend on **port 8001** (README says 8000) and pass `--no-proxy-headers` (see runtime gotcha below).
- `python-backend/.env` is the real config, but `main.py` also runs `load_dotenv("../.env.local")` — treat root `.env.local` as part of the backend's environment.

## Supabase is optional, not integrated
- The optional store activates only with `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` set **and** the `supabase` pip package installed (import is guarded; the line is commented out of `python-backend/requirements.txt`). Default persistence is SQLite in `python-backend/data/` (auto-created, git-ignored); uploaded images live in `python-backend/uploads/` (also git-ignored).
- **The live Supabase `contributors` table (created manually by the owner) differs from both the old migration and SQLite**: columns are `id uuid` (default `gen_random_uuid()`), `name`, `github_username` (NO unique constraint), `github_url`, `role`, `description`, `image_url` (single column), `display_order`, `created_at`, `updated_at`. `SupabaseContributorStore` translates at its boundary (`name`<->`display_name`, `image_url`<->`custom_avatar_url`) so the API/frontend keep the canonical shape; `avatar_url` stays empty because the frontend derives the GitHub avatar from `github_username` and `custom_avatar_url` is what renders.
- **Contributor ids are store-specific: SQLite `int` vs Supabase uuid string** — admin routes type the id path param as `str` and each store validates its own domain (`_coerce_sqlite_id` in the SQLite store, `_valid_id` UUID check in the Supabase store; invalid ids answer 404, never 500). Never change the path params back to `int`.
- The Supabase store blocks duplicate `github_username` with an app-level pre-check (raises `ValueError("duplicate github_username")` → API 409) because the live table has no unique constraint; keep that if the table is ever recreated with `unique`, since PostgREST duplicate errors are also classified by `is_duplicate_error`.
- PostgREST cannot query `information_schema` (PGRST205) and Swagger/OpenAPI components are empty — get a table's real columns from the Swagger 2.0 `parameters` row filters at `GET {SUPABASE_URL}/rest/v1/` with `Accept: application/openapi+json;version=1`, or probe `select=` with the suspected column names (a missing column errors `42703` naming it).
- **A doubled scheme (`https://https://…`) in `SUPABASE_URL` or root `.env.local`'s `NEXT_PUBLIC_SUPABASE_URL` fails with `getaddrinfo failed` deep inside httpx/postgrest — or, in the browser, a broken client with no obvious error.** The misleading error hides a config typo, not a network problem. The typo once existed in BOTH env files; check both. Verify the served config with `url.count('https://') == 1`, not a single `split('://')`.
- Tests must delete `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` from the env (see Testing) or they silently exercise the live Supabase project once those vars exist in `.env`.

## Runtime gotchas
- **uvicorn's `proxy-headers` mode is ON by default and trusts loopback**: it rewrites `request.client` from the spoofable `X-Forwarded-For` header, silently defeating any per-IP rate limiting keyed on it. Run uvicorn with `--no-proxy-headers` (both .bat files and READMEs do now); the app only reads the header when `TRUST_FORWARDED_FOR=true`. FastAPI's TestClient does **not** apply uvicorn's rewrite, so in-process tests cannot catch this class of bug — verify rate limiting against a real uvicorn server.
- Admin sessions and rate-limit state are per-process, in-memory singletons (`python-backend/admin_auth.py`): a server restart logs out every session **and** resets the limiter. Both behaviors are intended and covered by tests.
- Root `.gitignore` line `.env*` also ignores `.env.template`; it needs explicit negations (`!.env.template`, `!python-backend/.env.template`) placed after that line.
- The multipart image-upload endpoint requires `python-multipart`; importing `main` fails without it.
- FastAPI `FileResponse` page routes send ETag/Last-Modified, so browsers heuristically cache the HTML. When a page's content changes the security surface (the old contributors build carried admin UI on the public URL), serve `Cache-Control: no-store` — `/contributors`, `/contributors/admin`, and `/login` do.
- In the Preview tab, a plain navigation/reload can keep showing a stale cached copy of a changed page (and old cache entries predate new `no-store` headers). Force a fresh document with a cache-busting query (`/contributors?cb=1`) and refresh a changed shared asset with `fetch('/static/app.js', {cache:'reload'})` before verifying UI changes in-browser.
- Preview-page verification gotchas: an element can sit in the DOM at `display:flex` yet be invisible (`opacity:0` + `pointer-events:none`, shown via a `.show` class) — the accessibility tree and `getComputedStyle` both report it as visible, so check the toggle class. Assert "no API call leaked" with `performance.getEntriesByType('resource')` (`responseStatus` field) instead of the network tab. A `preview_evaluate` that dies with "Execution context was destroyed" mid-await usually means the page navigated/reloaded — re-snapshot, don't treat it as a failure.
- The live project may lack the `analyses` table: `GET {url}/rest/v1/analyses` answers `PGRST205` and `/api/history` answers a clean 503 **by design** until the owner pastes `supabase/migrations/20260904010000_create_analyses.sql` in the dashboard SQL editor (agents verify table absence over REST but cannot apply migrations). A 503/PGRST205 here is not a code bug — re-probe table existence before debugging.
- The Preview/headless browser **aborts external top-level navigation (`net::ERR_ABORTED`)**, so OAuth hops to github.com can never complete there (the GitHub button's 4s self-recovery in `login.html` exists for this). Verify OAuth config headlessly instead: `GET {url}/auth/v1/authorize?provider=github&redirect_to=<origin>` with the anon key must 302 to `github.com/login/oauth/authorize` (a 302 proves the provider and the redirect allow-list).

## Testing
- Tests run from `python-backend/`: `python -m pytest tests/`. The test module sets `RIZZ_MASTER_CODE`/`COOKIE_SECURE` **before** importing `main`, and isolates each test to a temp DB via a monkeypatched `CONTRIBUTORS_DB_PATH` — this only works because the SQLite store reads the env var at construction time, not via an import-time default arg. The autouse `clean_state` fixture also deletes the SUPABASE_* env vars so tests never hit the live Supabase project.
- `SupabaseContributorStore._from_db`/`_to_db`/`_valid_id` and `_coerce_sqlite_id` are static/module functions with hermetic unit tests in `tests/test_supabase_store_mapping.py` and `tests/test_store_ids.py` — extend those instead of testing the Supabase store over the network.
- `sqlite3.OperationalError: database is locked` or spurious 409s in pytest usually mean an orphaned `python -m pytest` process (e.g. from a timed-out run) still holds `python-backend/data/contributors.db`. Kill stray python.exe before re-running (`tasklist`; `wmic` may return nothing — use `powershell Get-CimInstance Win32_Process`), then delete `python-backend/data` and `python-backend/uploads`.
- `python-backend/__pycache__/*.pyc` files are **tracked in git**; running pytest/py_compile rewrites them, so run `git checkout -- python-backend/__pycache__/` before finishing to keep the diff clean.
- **To exercise a Supabase auth lifecycle live without real emails/GitHub creds**: create a disposable user via GoTrue admin API — `POST {SUPABASE_URL}/auth/v1/admin/users` with `{"email", "password", "email_confirm": true}` — log in through the real page with those creds, then delete it (`DELETE .../admin/users/{id}`, or list + filter by a `codebuff-probe-` prefix). Admin calls need BOTH `apikey` and `Authorization: Bearer` set to the service-role key; always clean up in a final step.

## Frontend conventions
- The navbar is now injected by `injectNavbar()` in `app.js` (replaces any per-page `<nav>` at runtime, derives active state from `location.pathname`). A navbar change touches ONE place (`app.js`), not every HTML file. `privacy.html` is the only page without `app.js` and keeps its own minimal `<nav>`.
- Contributors is split into TWO pages that must change together: `/contributors` (`frontend/contributors.html`) is the permanent public directory — it must never contain admin UI or call `/api/admin/me` (a pytest test forbids admin markers in its HTML) — and `/contributors/admin` (`frontend/contributors_admin.html`, route in `main.py`) is the auth-gated management page whose mutations rely on the server-side session+CSRF. Both pages share `frontend/contributors.css`; style edits go there, not inline.
- The site footer (in `app.js`) includes the discreet RIZZ-MASTER? link to `/contributors/admin`. Keep it in the footer's LEFT column under the tagline: the far-right bottom corner sits under the fixed chat FAB, which makes links there unclickable (the GitHub link already has this pre-existing overlap at full scroll-bottom).
- The lucide CDN has no `github` brand icon: `app.js` swaps `data-lucide="github"` for an inline SVG only for elements present at load. Dynamically-rendered github icons must embed that inline SVG directly or they render nothing and log a console warning.
- Backend CSP limits `img-src` to `'self' data: github.com avatars.githubusercontent.com` — avatar/image hotlinks must come from those origins.
- **Normal-user login (`/login`, `frontend/login.html`) is Supabase-managed and SEPARATE from Rizz Master admin auth** (admin = backend HttpOnly cookie + CSRF; user = supabase-js session the library persists). `frontend/auth.js` exposes `window.RR_AUTH` (config, client, signIn/signUp/signOut/getUser/onAuthChange) and injects an account chip into `nav .flex.items-center.gap-3` only when a session exists (never on `/login`). Don't put `data-lucide` icons in dynamically-injected nodes — `app.js`'s icon pass already ran.
- Every page that loads `app.js` must also load, BEFORE it: the pinned supabase-js UMD (`https://unpkg.com/@supabase/supabase-js@2.115.0/dist/umd/supabase.js`, mirrors the version in the untracked `frontend/package.json`) and `/static/auth.js`. OAuth `redirectTo` is `window.location.origin`, so the session-restore code can land on ANY page — `privacy.html` is the only page without `app.js` and is intentionally skipped.
- GoTrue OAuth uses PKCE (`response_type=code`) with the GitHub provider configured in the Supabase dashboard; the project URL must be whitelisted in Auth URL config for local origins. GoTrue answers HTTP 400 for wrong credentials — surface `error.message` only.
- `.env.local`'s `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are publishable by design (anon key, `sb_…` prefix) and safe to serve; keep every OTHER Supabase credential server-side.
- **Per-user analysis history (`python-backend/user_history.py`)**: every `/api/history` route depends on `current_user`, which verifies the bearer token server-side by calling GoTrue **`GET {url}/auth/v1/user`** — the legacy `/auth/v1/userinfo` endpoint 404s on current Supabase projects (silently breaking auth with "Invalid or expired session"). The user id is injected by the dependency, never taken from the body (`HistoryPayload` has `extra='forbid'`); rows go to the `analyses` table (migration `supabase/migrations/20260904010000_create_analyses.sql`, RLS = own rows) via service-role REST, and a missing table surfaces as a clean 503. Tests patch only the `_rest` network boundary + dependency override — patching `_insert`/`_delete` replaces the very functions that validate.
- Frontend auth UX (this pass): analysis triggers call `RR_AUTH.gate(url)` — logged out → LOGIN TO CONTINUE modal; continuation works via `/login|/signup?next=<path>` (email flows). GitHub OAuth `redirectTo` is the origin, so a `next` target is lost for the GitHub path only. History is account-tied: authed → `GET /api/history`; logged out → sign-in gate; localStorage fallback only when accounts are unconfigured. The nav auth zone must target the **LAST** `nav .flex.items-center.gap-3` — the left brand cluster uses the same classes.
- `auth.js`'s `onAuthChange` only re-renders the navbar — a page BODY whose content depends on the session (history) must subscribe itself and re-decide when auth flips on-page (logout from the chip while on the page otherwise leaves stale signed-in content). `history.html` reloads on a signed-in-state flip, guarded by a `currentAuthed` marker: the initial callback fires before init finishes and `TOKEN_REFRESHED` keeps the same state, so both must be suppressed or you double-fetch/reload.
- `auth.js` builds its supabase client through a single-flight promise — concurrent boot calls that both passed the `if (client)` guard used to create duplicate GoTrueClient instances (console warning, shared storage key). Keep every entry to `ensureClient()` single-flight.

## Windows tooling quirks
- Windows system `curl` cannot open Git Bash `/tmp` paths: `-F "image=@/tmp/x.png"` fails silently (empty body / HTTP 000). Use project-relative paths for multipart upload tests.
- Backgrounding a server with `&` inside a terminal command keeps the call running until timeout — launch the server, then run checks in separate commands. The listening PID from `netstat -ano | grep :PORT` differs from the shell `$!` PID; kill by the netstat PID.
- Two uvicorn instances can listen on the same port at once when one binds `0.0.0.0:PORT` and another `127.0.0.1:PORT`. Before restarting a dev server, kill EVERY pid from `netstat -ano | grep :PORT | grep LISTENING`, or your checks can hit a stale process running old code.
- The starter bats bind differently — `start-python-backend.bat` runs uvicorn on `0.0.0.0:8001`, `start-app.bat` on `127.0.0.1:8001`. Freebuff preview servers (also `127.0.0.1:8001`) outlive their session, so a later bat launch is shadowed: loopback connections go to the more specific `127.0.0.1` listener, and the browser hits the STALE server while the fresh one only answers non-loopback. "Backend not working through the file starter" = kill every LISTENING pid on 8001 (check BOTH `0.0.0.0` and `127.0.0.1` rows) before relaunching.
- PowerShell `Start-Process` with `$p = ...; $p.Id` fails when called through bash — bash expands `$p` to empty before PowerShell sees it. Escape with `\$p` or avoid assigning to a variable (pipe directly to `ForEach-Object { $_.Id }`).
- The `code_search` tool (ripgrep) is broken in this Freebuff environment (vendored rg missing) and hangs indefinitely on every call. Use `read_files` + manual inspection or `run_terminal_command` with `grep` instead.
